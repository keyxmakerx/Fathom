2 · Input focused — the SC 2.4.7 fix

54 §12 CSS · ADR-0026 (R37)

The input row inverts to --surface and gains a 2px --ink bottom rule. This replaces the old "the shell border is the focus indicator" position, which was a Level AA failure in the product's most-used surface: the shell border is present whenever the dialog is open, focused or not, and a caret is not a focus indicator. Click into the field below to see it. Phase 0 is where this ships — the AA claim in 55 §1.1 stays qualified until it does.

4 · Results — answer-shaped rows

The row is the answer, not the command. Each carries the question it answers (answers), what to read in the output (read_field) and, on the selected row, the first next_if_bad hop. Selection is the ▸ glyph plus --surface ground — no coloured bar, which 51 §4.2 forbids for selection by name.

5 · Ladder group — collapsed

16 §17.3 · 71 §3.5

Emitted when a State concept resolves BROAD and a matching ladder exists. It competes on score — it is not pinned to the top. Collapsed height is fixed at two steps, a rule and a count, so keystrokes never reflow the list. Order is ladder position, never score. Members are not repeated as flat rows below. → walks it; ↓ skips past it.

Ctrl K 7 · 1.1 ms
Bring-up order stop at the first failure
show security ike security-associations Read-only — safe on production P1 up? Index stable = it did not rebuild.
show security ipsec security-associations Read-only — safe on production P2 installed? State wants Installed.
+ 3 more steps · → walks the ladder

Installed proves crypto, not reachability. The tunnel reads UP while passing zero packets when st0 has no zone, no policy, or nothing routed at it.

  • show interfaces st0.0 terse Read-only — safe on production Is the virtual tunnel endpoint carrying an admin and link state of up?
  • show route 10.2.0.0/16 Read-only — safe on production Does the far side's prefix resolve, and out which interface?
  • clear security ike security-associations <peer-ip> Disruptive — drops live traffic How do I force the outer channel to rebuild with one far end? Tears down every child SA under P1 — on a hub that is every spoke at once. Always scope by peer or index.

7 · The three risks, in one list

51 §3.2 · ADR-0011 · 54 §12

Three risk colours, no fourth, and no other use of those colours anywhere in the row. Risk is a property of effect, not of verb (ADR-0011): clear is Disruptive because it drops traffic, not because of the word. The word is always visible as text, so the meaning survives monochrome print and forced colours.

8 · Miss — nothing above the cutoff

16 §19.5 · 16 §3.6

Below-cutoff entries are shown with their scores, because a user who can see the system nearly matched can adjust, and a user shown nothing cannot. The miss is logged locally and never transmitted; export misses writes a file the user reads before choosing to send it. Invariant 1 forbids telemetry — this log is the only instrument the project has, and it only works because it is not automatic.

9 · Known contradictions in the source

defects found while building this page

Two places where 54 §12's tables were not updated when the decisions above them landed. This page implements the current decision in each case — the prose and the CSS, which agree — and records the stale table rather than silently picking a side.

54 §12 "States" table contradicts R49 / ADR-0025 (6). The table still lists Result active | C3 + C1 | --surface ground + 4px --ink bar. The prose immediately above it, and the CSS below it, both delete that bar: selection is the ▸ glyph plus --surface ground. The table row needs deleting.
54 §12 "Accessibility contract" contradicts R37 / ADR-0026. It still reads "The input has no visible focus ring… this is a deliberate exception to 'focus is always an outline' and it is the only one." ADR-0026 revoked that as an SC 2.4.7 failure, and the CSS in the same section now inverts the input row on focus. The bullet needs rewriting to describe the inversion.
