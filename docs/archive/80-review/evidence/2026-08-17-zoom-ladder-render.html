The Zoom Ladder

One canvas, one zoom control, five depths — from a campus of sites down to a single port. The rack stops being a separate screen and becomes a rung.

You asked to zoom into a box and out to site data, all inside the canvas. The schema already supports most of it — but it declares two containment chains, not one, and that decides where the ladder forks. Below is each rung as the canvas would actually draw it.

2 · Where the ladder forks

This is the part your question answered itself. The schema declares two chains, and they are not variations of one — they hang off different roots:

Physical — where it is
  1. Premises (root)
  2. Rack HasRack
  3. Chassis MountedIn
  4. PhysicalPort HasPort
Logical — how it talks
  1. Site (root)
  2. Device HasDevice
  3. Interface HasInterface
  4. LogicalUnit → Address HasUnit, HasAddress

They meet at the chassis. A chassis is bolted into a rack (physical) and belongs to a device in a site (logical). That is the one rung where switching stance makes sense — and it means the answer to "physical view or logical view?" is neither: it is one ladder that forks once, at the box.

The consequence worth arguing with. A rack cannot appear in a site, and a site cannot contain a rack — HasRack runs from Premises, and HasDevice runs from Site. If you want "this rack is at the Denver site", that is a schema change, not a rendering choice. Worth deciding before anything is built.

3 · What it costs

The 900,000-byte ceiling is on the Rust module only. Page code lives in the HTML file, which has no ceiling. So the canvas swap is nearly free; the drag-and-drop is not.

Drag-and-drop is a move, so it needs the refusal reopened rather than worked around. Both module pieces must be measured against the 203 bytes currently free — which is an argument for doing the byte work first, not for a smaller design.

One thing I would insist on

Every rung needs a keyboard path. The product's rule is that a state only a mouse can see is not a state, and the browser drivers enforce it. So descending is a key as well as a click, and mounting is "select, then choose a U" as well as a drag.
